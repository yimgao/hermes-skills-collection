# Decision Journal Field Guide / 决策日志字段指南

## 必填字段

| 字段 | 合法值 / 格式 | 说明 |
|---|---|---|
| `title` | 非空字符串 | 用问题表达，例如“是否迁移到托管数据库” |
| `date` | `YYYY-MM-DD` | 冻结当时视角的日期 |
| `status` | `open / decided / reviewed / superseded` | 不自创近义词 |
| `owner` | 名称或角色 | 谁对最终决定负责 |
| `review_date` | `YYYY-MM-DD` | 应晚于或等于决策日期 |
| `reversibility` | `one-way / two-way` | 高退出成本用 one-way |
| `confidence` | 0–100 | 对核心预测的主观信心，不是事实概率 |

## 信息类型

- **Fact / 事实**：可被原始文档或可靠来源验证。
- **Inference / 推断**：由事实推导，必须允许被反驳。
- **Preference / 偏好**：价值取向，没有客观真假。
- **Assumption / 假设**：尚未验证、但决定依赖的命题。
- **Prediction / 预测**：带时间窗口和可观察结果的假设。

## 质量规则

1. 标准权重合计 100；不合计时不要输出总分。
2. 信心不要自动设为 50、80、90 等圆整数；先写支持与反对证据。
3. “成功”“更好”“稳定”不可直接作为验证信号，必须定义指标。
4. 一次复盘同时评估过程和结果，避免结果偏差。
5. 原始记录不可覆盖；修正以带日期的 amendment 追加。
6. `superseded` 表示出现新决定替代旧决定，必须链接新条目。

## 复盘提示

- 哪个核心预测偏差最大？
- 哪条证据当时存在但被忽略？
- 哪条信息是后来才可能知道？
- 假设失败，是判断错误、执行失败还是外部冲击？
- 下次应改变阈值、信息源、实验设计还是退出条件？

## 隐私边界

不要记录密码、API token、恢复码、完整身份证件号码、银行卡号或未脱敏医疗原件。需要共享或提交 Git 时，用角色替代真实姓名，并把敏感金额区间化。
